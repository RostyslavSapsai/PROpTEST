# PROpTEST v2 · S3-Connect 0.3.0

Цей етап додає оновлення ESP32-S3 через Wi-Fi та короткий тест старого Hobbywing ESC на **GPIO14**. Це не прошивка вимірювання тяги: датчики ще не активовані, запис експерименту в Avalonia залишається заблокованим. Uno PT:2.2 не змінена.

## Як користуватися

1. Запустіть `START-v2.cmd` або `artifacts/windows-v2-connect-030/PropTest.Desktop.exe`.
2. На вкладці «Підключення» натисніть **«Плата: оновлення й тест»**. Плата й ноутбук мають бути доступні в одній локальній мережі; інтернет ноутбука не потрібно вимикати.
3. На сторінці введіть пароль **власної мережі плати**, який програма показує через USB. Це не пароль домашнього роутера. Пароль можна скопіювати; сторінка не зберігає його в localStorage.
4. Для оновлення виберіть `artifacts/firmware-s3-030/PROpTEST-S3-0.3.0.ptfw` і натисніть «Завантажити оновлення». Надалі використовуються пакети наступних версій. Звичайний `.bin`, merged image або прошивку Uno цей інтерфейс не приймає.
5. Залиште сторінку відкритою: після перезапуску вона перевіряє API та підтверджує запуск. Без підтвердження за 60 секунд нова версія повертається до попередньої. Налаштування домашнього Wi-Fi зберігаються.

Поточна адреса цієї плати була `http://192.168.3.62/`, ім’я — `proptest-v2-858428.local`. DHCP може змінити IP; актуальну адресу програма читає через USB. Запасна мережа плати використовує `192.168.4.1`.

## Тимчасовий тест старого ESC

- Білий сигнальний провід → **GPIO14**, чорний → **GND ESP32**. Силове живлення ESC — від акумулятора, не від ESP32. GPIO20 не використовувати для ESC: це USB.
- Перше випробування нового контролера — **зі знятим пропелером**. Перевірка на голій платі не перевіряє фізичну зупинку ESC/мотора.
- «Підготувати тест» залишає нульовий газ. Потім ввести число від 0 до 10%, крок 0,1%, натиснути «Задати газ».
- Незнімний ліміт прошивки **10%**, до **30 с** на сесію. Новий тест потребує окремої підготовки. Немає автоматичного запуску після перезавантаження, перепідключення чи оновлення.
- PWM: 50 Гц, 1000–1100 мкс; 14-бітний LEDC, крок таймера приблизно 1,22 мкс. Відсотки — команда ESC, не відсоток обертів або тяги. Ненульовий вихід змінюється на 0,1% за 20 мс; нуль задається без плавного зниження.
- Окреме завдання на ESP32 перевіряє lease кожні 20 мс. Без авторизованих команд сесії 1000 мс — нуль і роззброєння. HTTP-парсер не керує цим таймером. Завдання підписане на watchdog 2 с.
- STOP доступний у браузері та через `G` USB/TCP. Перед підтвердженням перевіряється програмний стан застосованого нульового виходу. Це не вимір тривалості імпульсу осцилографом і не датчик зупинки ротора.
- Приховування вкладки припиняє тест. Втрата Wi-Fi дає повідомлення з непідтвердженим станом, а не фальшиве підтвердження нуля.
- GPIO10–13, зарезервовані для майбутнього 4-in-1 ESC, не налаштовуються. GPIO14 — лише тимчасова конфігурація.

## Оновлення і відновлення

Arduino ESP32 **3.3.12**, ESP-IDF **5.5.5**. Встановлений SDK має `CONFIG_BOOTLOADER_APP_ROLLBACK_ENABLE=y` та `CONFIG_APP_ROLLBACK_ENABLE=y`. Стандартна таблиця містить app0/app1 по `0x140000` байтів та otadata; таблиця й NVS при OTA не переписуються.

Пакет: 16 ASCII-байтів `PROPTEST-S3-OTA1`, uint32 little-endian довжина образу, 64 ASCII hex SHA-256, байти application `.bin`. Перевіряються magic, точний розмір, SHA-256 і валідність ESP-образу бібліотекою Update. SHA-256 захищає від пошкодження файла; це **не цифровий підпис видавця**.

Прошивка перевизначає `verifyRollbackLater`, щоб Arduino не підтвердила образ до запуску застосунку. Підтвердження через API вимагає працездатного завдання виходу та Wi-Fi AP. Воно перевіряє запуск і зв’язок, але не правильність усієї логіки чи датчиків. До підтвердження запуск мотора заблокований. Для невідновлюваних помилок залишається прошивання через USB/BOOT/RESET.

HTTP на порту 80: пароль плати, Basic authentication, обов’язковий `X-Proptest: 1` для API; CORS не відкрито. Доступ тільки в довіреній LAN/AP, без перенаправлення порту з інтернету. HTTP не шифрує трафік; HTTPS/підписані пакети — окремий наступний етап, не реалізований тут.

TCP/USB ідентифікатор `PT:S3:0.3`; старі P/H/I/NET збережені. Команди газу через цей протокол не додані. Керування тестом — через авторизовані HTTP POST `/arm`, `/gas` (ціле 0–100, десяті відсотка), `/lease`, `/stop`. Сесія має випадковий token; старий token не відновлює роззброєний вихід. `/status` не поновлює lease. `/confirm` підтверджує новий запуск; `/update` приймає multipart файл. Оновлення під час активної сесії відхиляється.

## Збирання та перевірки

### Перевірено 2026-09-30

- Збірка .NET: без помилок і попереджень; 56 тестів пройшли. Окремо після OTA пройшов опційний тест реальної ESP32 на COM7 (автовизначення, heartbeat, Stop, повторне підключення).
- На голій ESP32 через Wi-Fi: досягнення програмного виходу 10% з обмеженням; lease timeout; відхилення старого token; відхилення газу >10%; зупинка при завислому HTTP-запиті; завершення за 30 с; заборона OTA під час активного тесту.
- Відхилення неправильного пакета та образу з пошкодженим SHA-256. Поточна прошивка залишалася працездатною.
- Реальне OTA у другий розділ і автоматичне повернення через 60 с без підтвердження. Потім успішне оновлення через сторінку браузера в app1 і фінального пакета через Wi-Fi в app0: `pending=false`, GPIO14, `armed=false`, заданий і застосований газ 0.
- Інтерфейс переглянуто у браузері та на знімку Avalonia. Дві візуальні ітерації, оцінка 9/10; виправлено видимість повідомлення при прокручуванні. На ширині 390 px горизонтальне переповнення не виявлено. Повноцінного тесту на фізичному телефоні не було.

`scripts/build-s3.ps1` збирає application і `.ptfw`; параметр `-Port COM7` додає USB-прошивання. `scripts/build.ps1 -Publish` збирає Windows-пакет. Переносити потрібно всю папку з EXE.

`scripts/test-s3-ota.ps1 -BareBoard -Mode Check|Update|Rollback` — явний тест **лише голої плати без ESC і датчиків**, із USB для локального читання пароля. Самі API та OTA перевіряються через Wi-Fi. Команди тесту можуть активувати GPIO14; не запускати скрипт із підключеним ESC.

Детальні результати поточного запуску — `artifacts/hardware-diagnostics/s3-030-*.json`, журнал першого USB-завантаження — `s3-030-usb-upload.log`. Резервна копія NVS/otadata — `s3-pre-ota-nvs-030.bin`; вона містить приватні налаштування і не призначена для публікації. Спроба повної резервної копії `s3-pre-ota-030.bin` перервалася: не використовувати цей файл для відновлення.

Фізичні перевірки, які залишаються: форма PWM осцилографом, сумісність 3,3 В сигналу зі старим ESC, запуск/зупинка мотора без пропелера, час зупинки при реальному обриві Wi-Fi/живлення. Вимірювання датчиків, струмове відсічення та калібрування S3 у цій версії відсутні.

Джерела: [ESP-IDF 5.5.5 OTA](https://docs.espressif.com/projects/esp-idf/en/v5.5.5/esp32s3/api-reference/system/ota.html), [LEDC API](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/ledc.html); фактичні сигнатури Update/WebServer та rollback перевірені у встановленому core 3.3.12.

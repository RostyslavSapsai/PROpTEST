# Uno PT:2.2 — поточний протокол

[Зміст](README.md) · [Архітектура даних](ARCHITECTURE.md)

Це опис локального `PropTestUno.ino`, перевірений читанням коду 2026-09-15. Він не є специфікацією майбутньої ESP32-прошивки. Історичні скетчі GitHub можуть не підтримувати ці команди.

## Транспорт та команди

USB serial: **115200, 8N1**, рядки LF; команди чутливі до регістру. Desktop встановлює DTR/RTS false, але це не гарантує відсутність reset при відкритті порту. Максимум команди — 39 символів; переповнення вхідного рядка роззброює пристрій.

| Команда | Поведінка |
|---|---|
| `P` | Відповідь `PT:2.2`, без армінгу |
| `G` | Stop/disarm, PWM 1000 мкс, `ACK:G:0` |
| `B` | Stop, потім армінг на нулі; після перших 3 с uptime; `ACK:B:0` |
| `H` | Оновлює heartbeat лише коли armed; не армує |
| `M:n` | Стеля газу, ціле n від 1 до 30, лише disarmed |
| `F:n` | Інтервал телеметрії 50–2000 мс, лише disarmed |
| `W:n` | Цілий відсоток газу, 0…стеля, лише armed |
| `U:n` | Десяті відсотка, 0…10×стеля, лише armed; U:61 означає 6,1% |
| `Q` | Одна діагностична вибірка, доступна також disarmed |
| `A` | `SOUND|last_min|last_max|last_sample_count` |
| `I` | Діагностика контактів/ADC; повне сканування I2C лише disarmed |

Не всі команди мають ACK. Desktop явно очікує підтвердження Begin/Stop; timeout очікування у поточному адаптері 600 мс. Приклад без ненульового газу: `P`, `G`, `M:10`, `F:200`, `B`, періодичні `H`, `G`. Навіть такий приклад не є дозволом запускати неперевірену механіку.

## Телеметрія Uno

```text
D|sequence|uptime_ms|applied_pct|hx_raw|current_a|x_g|y_g|z_g|sound_adc|armed|historical_thrust_g
```

- `sequence` — номер кадру; на B скидається лічильник.
- `uptime_ms` — uptime контролера, не UTC.
- `applied_pct` — застосована команда газу, не RPM/тяга/потужність.
- `hx_raw` — сирий відлік HX; `historical_thrust_g` — історичне перетворення.
- `current_a` — номінальна оцінка ACS712.
- `x_g/y_g/z_g` — прискорення у g разом із гравітацією.
- `sound_adc` — амплітуда ADC; для 2.1/2.2 середній розмах 50-мс вікон.
- `armed` — 0/1. Desktop для запису поточного протоколу приймає armed=1.

Відсутні канали — порожні поля. Desktop приймає 11/12-польові кадри сумісності, а для 12-польового застосовує полярність −1 до історичної тяги. Внутрішній формат `PT2|S|...` утворюється вже на ПК.

## PWM, час і відмови

Формула поточної прошивки: `PWM_us = 1000 + 10 × applied_percent`. Тут PWM_us — ширина імпульсу в мікросекундах, applied_percent — відсотки. При 10%: 1000 + 10×10 = 1100 мкс. При стелі 30% максимум 1300 мкс. Це налаштування поточного ESC, не універсальна відповідність тяги відсоткам.

Ненульовий газ змінюється кроком 0,1% не частіше ніж раз на 10 мс. Нуль застосовується негайно на рівні сигналу. Високого стартового імпульсу й автоматичного калібрування кінцевих точок ESC немає.

| Подія | Реакція |
|---|---|
| Heartbeat відсутній понад 1000 мс | Stop/disarm, `FAULT:HEARTBEAT` |
| Непридатний струм при ненульовій команді, оцінка ≥8 А за модулем | Відмова ненульового запуску або Stop, `FAULT:CURRENT` |
| Зависання основного циклу | MCU watchdog; фізичний час зупинки не встановлено |
| B раніше 3 с uptime | `ERR:STARTUP` |
| Некоректна команда/число/стан | `ERR:COMMAND`, `ERR:VALUE` або `ERR:LIMIT_OR_STATE` |

Поточний контроль струму виконується приблизно кожні 50 мс. Поріг 8 А працює від некаліброваної оцінки та не замінює запобіжник/силове відключення. Heartbeat надсилається desktop приблизно раз на 200 мс під час тесту. Окремий timeout телеметрії ПК — max(2000 мс, 3×інтервал).

Не всі помилки синтаксису прошивка сама перетворює на Stop; desktop обробляє ERR як помилку сесії. PT:1.0 не має тих самих гарантій heartbeat/ACK, тому сумісність старих кадрів не означає однакову поведінку захисту.
